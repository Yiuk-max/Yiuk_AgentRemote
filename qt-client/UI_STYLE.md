# Qt 客户端界面风格规范

本文是 Yiuk Device Assist Windows 客户端的界面实现约定。新增页面、弹窗、菜单和提示时应遵循本文；已有实现与规范不一致时，优先复用现有公共组件并逐步统一，避免另起一套视觉风格。

## 1. 整体方向

- **清晰、克制、可信赖**：这是 Agent 远程协助工具，界面以信息辨识和安全状态表达为先，不做装饰性堆叠。
- **主窗口、普通子窗口和对话框使用同一套浅色设计语言**：白色表面、冷灰色分区、深色正文、蓝色主操作、统一圆角与边框。子窗口不使用系统原生标题栏或另一套控件皮肤。
- 页面间共享颜色、字号、按钮和图标规则。优先使用客户端已有的 `YiukDialog`、`TitleBar`、`makeLabel`、`makeButton`、`makePrimaryButton`、`makeDangerButton`、`iconButton` 和 SVG 资源，不为单个页面复制一份 QSS。
- **例外：远程活动面板**是桌面悬浮的只读状态面板，采用半透明深色底，以便覆盖在任意桌面壁纸上仍清晰可读。它与主程序在品牌、圆角卡片、信息层级和状态语义上协调，不要求强行改成白色普通窗口。

## 2. 主窗口布局

- 主窗口使用无边框自绘标题栏，整体为左侧导航栏、右侧页面内容和右侧底部状态栏。
- 默认尺寸为 `960 × 600`，最小尺寸同为 `960 × 600`；页面内容按纵向滚动或弹性布局适配，不应靠增加页面空白或巨大按钮填满空间。
- 左侧导航使用浅灰底，当前选中项以淡蓝灰背景和蓝色文字标识；页面主体以白色为主。
- 页面标题清楚、靠左；页面说明文字紧跟标题，字号和颜色弱于标题。内容区边距保持宽松但适度，卡片之间的间距一致。
- 重要信息放在浅灰或白色卡片中，卡片边界使用细线，不用厚重阴影或多层嵌套卡片。

## 3. 配色

以 `qt-client/src/mainwindow.cpp` 中的全局 QSS 和 `qt-client/src/main.cpp` 中的应用调色板为实现基准：

| 用途 | 颜色 | 说明 |
| --- | --- | --- |
| 页面与卡片主背景 | `#ffffff` | 保持干净、统一 |
| 主文字 | `#182230` | 正文、重要信息 |
| 次级文字 | `#536174`、`#5f6d80`、`#687588` | 描述、标签、辅助信息，按层级使用 |
| 弱化文字 | `#7a8798`、`#69788d` | 页面说明、状态补充 |
| 主操作蓝 | `#1479ed` | 主按钮、焦点边框、交互强调 |
| 蓝色悬停/选中 | `#096bd7`、`#126fe0`、`#e8f1fd` | 按钮悬停、导航与菜单选中状态 |
| 侧栏/信息底色 | `#f1f4f8`、`#f5f7fa` | 导航区、身份信息区 |
| 卡片/输入框边框 | `#e1e7ef`、`#cbd5e1` | 使用细边框，避免强对比 |
| 危险操作 | `#a52b2b` 系 | 只用于破坏性或不可逆操作 |
| 安全提醒 | `#8a5b14`、`#fff6e5` | 权限和风险说明，不用作一般装饰 |
| 成功/在线状态 | `#16825d` | 在线、成功等正向状态 |

颜色必须承担明确语义，不要仅为区分页面而随意引入新色。状态信息同时提供文字，不只靠颜色表达。

## 4. 字体与信息层级

- 使用系统 UI 字体；仅设备码、临时密码等定长标识可使用等宽字体（例如 `Consolas`）。
- 页面主标题约 `22px`、粗体；区块标题约 `16–19px`、半粗；正文通常 `13–14px`；辅助说明和状态约 `11–13px`。
- 标题、正文、说明应通过字号、字重和颜色建立层级，不以全大写、长段粗体或大量强调色制造层级。
- 标签和说明应简短、准确；可能较长的说明必须换行，避免裁切或横向挤压。

## 5. 卡片、边框与尺寸

- 普通卡片使用白底、`1px` 浅灰边框，圆角通常 `8px`；身份信息卡可使用淡灰底和较大的圆角（约 `14px`）。
- 输入框和一般按钮圆角约 `6px`；图标按钮保持紧凑、方形点击区。全局统一使用细边框和克制的 hover 背景。
- 控件之间对齐，页面操作放在所属区块的标题行或操作行内。避免单个按钮漂在左侧/右侧、与所属内容分离，或为了按钮额外增加一整行空白。
- 页面卡片内边距通常为 `8–16px`；同一行控件间距约 `8–14px`。减少无必要的纵向 padding 和空白。

## 6. 按钮、图标与交互

- 一个区块最多设置一个主要蓝色操作；普通操作用白底细边框按钮；危险操作使用独立危险样式并在执行前确认。
- 图标按钮用于复制、刷新、显示密码等简单、频繁、空间有限的动作。必须设置准确的 `toolTip` 和 `accessibleName`；鼠标悬停提示提供必要的小字说明。
- 图标按钮应放在与其功能对象相邻的位置，或放在区块标题行的末端。避免把多个无文字图标散放在不相关区域。
- 图标集中放在 `qt-client/resources/`，文件名使用清晰、稳定的语义名称（例如 `home.svg`、`copy.svg`、`eye-open.svg`）。在 `resources/qt-client.qrc` 注册后，通过 `QIcon(":/icons/...")` 或 `glyphIcon()` 使用；不得依赖用户当前目录中的资源文件路径。
- 同一功能状态需有一致的图标与提示文案；选中、按下、禁用状态应清楚可辨。

## 7. 子窗口与对话框

- 一般次级窗口、确认框、输入框、安全提示和错误提示统一使用 `YiukDialog`，复用自绘 `TitleBar` 和共享按钮工厂。不要直接调用 `QMessageBox` 或 `QInputDialog`，避免出现 Windows 原生边框、字体和按钮风格。
- `YiukDialog` 使用透明窗口外层、白色圆角视觉卡片、浅色投影、细边框；标题栏左侧显示短标题，底部操作按钮靠右排列。对话框宽度按内容设置，并允许正文换行。
- 输入提示应放在说明文字之后；取消与确认操作在同一行，确认按钮使用主色。危险操作不能默认选中，也不能让 Enter 键误触发。
- 子窗口应与主窗口共享应用调色板和 QSS 语义，不能自行设置整套互相冲突的颜色、字体或控件样式。
- 菜单和工具提示虽是独立弹出层，也遵循白底、细边框、深色文字和浅蓝选中/悬停状态。

## 8. 状态与安全信息

- 等待批准、活动、已结束、失败、过期等状态使用稳定、清楚的中文文案，并配合对应的辅助色。
- 涉及远程执行、权限、密码、证书或文件写入时，说明要准确、可读且不隐瞒风险；风险提醒与普通帮助提示明确区分。
- 不在普通提示、工具提示或 MCP 配置片段里暴露临时密码、Player 密码或其他凭据。

## 9. 活动面板风格

活动面板是独立的只读悬浮窗，有意采用透明深色玻璃卡片，而不是普通白色设置窗：深冷灰底、浅色正文和细白色分隔线。会话、执行、读取、下载、上传、成功、错误等事件使用固定语义色；正文仍应保证对比度和可读性。不要把它做成可输入命令的远控终端，也不要让新增活动自动抢占用户前台焦点。

## 10. 新界面提交前检查

- 是否复用统一的窗口、对话框、按钮和图标组件？
- 主窗口及普通弹窗是否保持白底、冷灰辅助色、蓝色主操作的共同风格？
- 按钮是否靠近对应标题或内容，没有形成尴尬的孤立行？
- 是否避免多余的垂直留白、过宽按钮和过长说明？
- 所有图标按钮是否有 tooltip / accessible name？所有错误、风险和状态是否有文字说明？
- 弹窗、菜单和提示在 125% DPI 下是否仍完整、可读、可操作？
- 远程活动面板是否仍保持只读、半透明深色和不抢焦点的特性？
