# 用户询问功能：自测与整改记录

本文件记录第二轮自查：第一版虽然链路与单元测试都通过，但界面是“表单 + 单选框 + 说明文字”的堆砌，实际用起来不像正常交互。以下是我自己看着真实窗口、逐项检查后做的整改。

## 一、第一版的问题（自查结论）

1. 交互模型自相矛盾：既有单选框又有输入框，还隐藏了“输入文字自动勾选其他回答”的规则。
2. 多出无意义元素：倒计时每秒跳动、`最多 1000 字；回复不会额外授予操作权限` 这类说明、固定的“其他回答”单选项。
3. 布局有空块：滚动区域被强制设了最小高度，问题少的时候中间出现大片灰白空洞。
4. 正文底色错误：滚动区域视口用了平台灰底，在白卡片里像贴了一块灰布。
5. 键盘行为错误（第一版就有，测试没覆盖）：输入框为空时按 Enter 会触发对话框的“隐式默认按钮”，直接选中第一项并把答案发出去；标题栏的关闭按钮同样可能被 Enter 触发。
6. 窗口可能被遮挡：客户端常驻托盘，Windows 不允许后台程序抢前台，询问窗口可能就停在别的应用后面，用户根本看不到。
7. 只验证了“控件能被点到、返回值对不对”，没有验证“人看见这个窗口知不知道怎么用”。

## 二、整改后的交互

- 删掉单选框与“其他回答”项：**每一项就是一个整行按钮，点一下即为回答**。
- 保留一个始终可见的输入框，占位符“也可以直接输入你的回答…”，有内容才可发送，Enter 发送。
- 底部只保留“暂不回答 / 发送”两个动作；关闭按钮、Esc、暂不回答三者等价为 `cancelled`。
- 去掉倒计时和说教式提示文字；窗口自己到期关闭，状态由平台权威收敛。
- 所有选项按钮与标题栏按钮都关闭 `autoDefault/default`，空输入按 Enter 不再误答。
- 询问窗口置顶并请求前台；主窗口隐藏时额外发一条托盘提醒。
- 只有内容超过约 620px 才启用滚动，且只滚动问题与选项，输入框和按钮固定；滚动条改为与客户端一致的浅色细条（全局 QSS，一并改善设置页与会话列表）。
- 长问题文字按实际宽度换行，不再出现“文字一行、盒子两行高”的空洞。
- 位置跟随所有者窗口居中；owner 隐藏时按鼠标所在屏幕居中，并按窗口边框（含 Windows 无边框窗口的隐形边）夹到可用区域内。

## 三、验证方式

- 用真实生产客户端验证，而不是只看测试工具：`yiuk-mcp.exe`（MCP stdio）→ 本地真实平台 → `yiuk-device-assist.exe`，会话为直连授权，`ask_user` 后窗口真实弹出。用 `PrintWindow` 抓取该窗口位图确认渲染结果（截取的屏幕区域会被其它全屏应用盖住，不能作为证据）。
- 端到端测试程序 `yiuk-question-interop` 直接编译生产 UI 源码，自动操作真实控件：选项、输入+Enter、纯输入、长文本、Esc、关闭、暂不回答、超时、会话停止、设备断线。
- 100%、125% 渲染截图均核对；超长内容进入滚动路径单独核对。
- `go test ./...`、`go vet ./...`、`go test -race`（question / gateway / platformclient / edge）通过。
