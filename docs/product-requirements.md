# Yiuk Switchboard 产品需求文档

版本：1.2  
阶段：MVP 开发中  
目标平台：Windows 10/11 x64  
关联文档：[架构与实现](architecture.md)、[开发与构建](development.md)

## 1. 产品定义

Yiuk Switchboard 是面向 AI Agent 的远程 Windows 设备协助平台。操作者在本机运行 Agent；设备所有者通过明确授权，允许操作者在限定会话中远程执行命令并读取结果。操作者和设备所有者使用同一款 Windows Qt 软件，按角色启用相应界面/功能。支持 MCP 的 Agent 通过统一工具接口调用平台能力。

Minecraft 联机不是新产品的主要场景，但属于必须保留的既有能力。后端、网络协议和 Minecraft MOD 可以为新架构调整；保留范围须在实施前形成可验证的兼容清单。

## 2. 目标与非目标

### 目标

- 普通 Windows 用户可安装、注册设备、理解授权请求并随时终止会话。
- 至少一种 Agent 经统一工具核心和 MCP adapter 完成设备查询、申请授权、命令执行和多轮结果读取。
- 所有远程命令均绑定到设备所有者批准的会话；命令以普通用户权限运行，默认不提权。
- 网络经加密中转，正确处理超时、取消、断线和结果未知。
- 保留冻结清单中的 Minecraft 联机行为。

### MVP 不做

远程桌面/屏幕控制、交互式永久 shell、无人值守永久授权、管理员权限默认执行、macOS/Linux 设备端、组织租户/计费/算力市场、集群任务调度。

## 3. 用户与使用场景

### 设备所有者/被协助者

朋友或用户持有需要排查问题的 Windows 电脑，安装 Yiuk Switchboard、完成设备注册并保持客户端在线。有人申请协助时，用户看到操作者身份、用途、申请权限和有效期，选择批准或拒绝。批准后可看到当前操作者和任务，并可立即结束会话。

### 操作者/协助者

技术协助者在自己的 Windows 电脑安装同一产品，选择目标设备并发起请求；也可通过 Agent 完成这些操作。Agent 在本机运行，不要求目标设备运行模型。

### Agent

支持 MCP 的 Agent 使用本机启动的 MCP adapter。它通过统一工具契约列设备、申请连接、查询批准状态、执行命令、获取结果、取消任务和关闭会话。替换 Agent 不应要求修改设备执行核心或服务端业务。

## 4. 关键用户流程

### 4.1 安装与设备注册

1. 用户从可信发布渠道下载签名安装包并安装同一款 Qt 软件。
2. 软件提供设备所有者/协助者功能；用户可在同一设备启用适用角色。
3. 设备所有者登录或完成配对，客户端创建设备身份并保护本地凭证。
4. 客户端主动建立加密连接，显示设备名称、设备码、在线与会话状态。

验收：无需开发工具、命令行或端口映射完成安装注册。设备码只能标识设备，不能单独认证。

### 4.2 连接和批准

1. 操作者 UI 或本机 Agent 指定目标设备、用途和所需权限。
2. 服务端确认操作者有权申请并通知目标设备。
3. 设备 UI 显示请求者身份、请求时间、用途、权限、有效期。
4. 所有者批准/拒绝；过期请求自动失效。
5. 只有批准后该会话才能执行命令。批准绑定设备、操作者、会话、权限和到期时间。

验收：未批准、被拒绝、过期或被撤销的会话不能执行任务。

### 4.3 执行与结束

1. Agent 或操作者提交单条 PowerShell 命令及可选工作目录、超时。
2. 设备端创建有界任务，返回 stdout、stderr、退出码和明确任务状态。
3. 操作者/Agent 根据结果继续下一条命令。
4. 任一方均可关闭会话；设备所有者可立即撤销并终止正在运行的任务。

验收：能正确处理多轮任务、输出分块、输出截断、超时、取消、断线及无法确认结果。

## 5. 产品功能需求

### 5.1 统一 Windows Qt 客户端

- 同一产品和安装包提供所有者与协助者能力，不要求两个用户用不同客户端。
- 显示登录/配对、设备码、在线状态、会话请求、活动操作者、任务和断开入口。
- 支持复制设备码、设备注销/凭证撤销、正常升级与卸载。
- UI 不阻塞于网络或进程执行；断线、权限不足及错误应可理解。
- 默认不静默常驻、不隐藏远程活动状态。任何后台服务模式必须显式安装、可见并可停止。
- 远程活动面板只读、可随时关闭与重新打开：关闭不影响会话，新操作不得自动将其弹出或抢焦点；只展示当前会话，按操作类型（读取、执行命令、下载、输出、错误）区分展示，不提供会话切换。

### 5.2 身份、设备与会话

- 每台设备具有独立凭证；设备码与认证凭证分离。
- 支持设备注册、在线/离线状态、重新配对和撤销。
- 会话状态至少包含 `pending_approval`、`approved/active`、`rejected`、`expired`、`closed`、`interrupted`。
- 并发设备/会话/任务有服务端限制。
- 授权不可跨设备、操作者或会话复用。

### 5.3 命令任务

- 单次命令执行，不提供无限期交互 shell。
- 回传 stdout、stderr、退出码、请求 ID、状态和是否截断。
- 支持工作目录、超时、取消、输出大小上限、任务并发限制。
- 防止请求重放导致非预期重复执行；断线后结果不确定时返回 `result_unknown`，不自动重试。
- 默认普通 Windows 用户权限。管理员提升不在 MVP 默认能力中。

### 5.4 Agent 工具核心与适配器

统一能力至少包含：`list_devices`、`get_device_status`、`request_connection`、`run_command`、`get_session_status`、`execute_command`、`get_command_result`、`download_file`、`cancel_command`、`close_session`。其中 `run_command` 为便利工具，在平台 backend 上一次性完成“申请会话—等待批准—执行—取结果—关闭”；`download_file` 必须在显式授予 `read_file` 权限的会话中调用，把受限大小的远端文件下载到 agent 本机。

每个工具定义严格参数 schema、结构化结果、稳定错误码、超时和取消语义。MCP 是首个适配器，通过 stdio 与本机 Agent 通信；MCP 不实现授权本身。核心能力可后续接 CLI、HTTP 或其他 Agent 适配器。

### 5.5 Go 平台服务

- 管理账户/设备凭证、在线状态、连接申请、批准、会话授权和任务路由。
- 使用加密传输，支持版本化帧、双向中转、心跳、deadline、限流、背压、最大消息和异常清理。
- 远程协助与 Minecraft 使用独立业务类型和授权/资源边界。
- 审计必要元数据和状态，不默认长期保存完整命令/输出。
- 后端可采用现有 relay 改造、拆分、重写或新旧并行部署，由技术评估决定。

### 5.6 Minecraft 兼容

产品必须保留阶段一冻结的 Minecraft 联机用户可见能力。可能涉及模组认证、开房、列房、加入、房主断线恢复和实际双向游戏流，具体按当前既有功能确认。后端架构、协议与 MOD 可调整，但发布前必须执行目标 Minecraft/loader 组合的端到端回归。只通过 Go 单测或 MOD 编译不算完成。

## 6. 安全、隐私和信任

- 远程连接必须由设备所有者明确批准；用户能随时拒绝和终止。
- 连接采用 TLS 并校验证书；认证凭证需安全存储、可撤销，不进入日志。
- 命令以当前登录用户权限执行；Qt 客户端/Agent 不应静默提权。
- 明确提示：PowerShell 命令在该用户权限范围内可读写文件和修改系统；普通用户权限不构成沙箱。
- 执行有时间、输出和并发限制；取消处理子进程树。
- 审计操作者、设备、授权结果、任务状态、起止时间和结束原因；默认不保存完整输出。
- TLS 在中转终止时服务端可见应用数据。若威胁模型要求中转不可读，端到端加密须作为单独发布门槛。
- 不把隐藏控制、绕过用户同意或凭设备码执行命令作为产品能力。

## 7. 非功能需求

- 断网/重启后能区分离线、失败、取消和结果未知；不谎报成功。
- 任务输出分块并受限，慢连接不得无限占用内存。
- 协议版本化，业务模块可独立测试，Agent adapter 不改变设备核心。
- Windows 10/11 x64 安装、首次启动、升级、卸载均纳入验收。
- 可观测在线设备、活跃会话、授权结果、任务状态、连接错误和转发流量，且不泄露秘密。

## 8. MVP 验收标准

1. 两名用户可在两台 Windows 电脑安装同一款软件并完成设备注册。
2. 设备所有者可识别设备、在线状态和操作者请求并批准/拒绝。
3. 未批准的会话无法执行命令；所有者可随时终止会话。
4. 至少一个 Agent 通过 MCP 完成申请、等待批准、执行、读结果和继续执行。
5. stdout、stderr、退出码、超时、取消、输出限制和断线结果正确。
6. 凭证撤销、跨会话访问和重复请求测试通过。
7. 传输经过 TLS，认证信息不明文存储或写入日志。
8. Minecraft 冻结兼容清单在目标环境通过端到端回归。
9. 更新 Agent adapter 不需要重写 Windows 执行模块。

## 9. 成功指标

关注设备注册成功率、请求批准/拒绝路径正确率、授权会话建立率、任务结果正确率、超时/取消/断线清理率、Agent 调用成功率、Minecraft 回归通过率和用户能否可靠立即断开。性能目标在首轮跨网络原型后量化。

## 10. 关键待决事项

1. 账户/身份提供方和设备配对方式。
2. 应用退出后设备是否保持在线；是否需要 Windows Service/托盘模式。
3. MCP adapter 与 Qt Core 的进程/IPC 边界及首个真实 Agent。
4. 服务端长期数据（账户、设备、审计）存储方案。
5. 中转 TLS 可见性是否符合威胁模型，是否需要端到端加密。
6. Minecraft 联机的确切保留清单、版本矩阵及新旧服务并行策略。
7. 安装包签名、自动升级和发布渠道。

在这些事项未决期间，以[架构与实现](architecture.md)中的建议基线做 spike，不应把建议视为不可更改事实。
