# Agent 向设备用户提问：最小实现计划

状态：已实施。使用方式和测试命令见 [user-questions.md](user-questions.md)。下文保留原实施规划；实际调整见文末。

## 1. 目标与边界

Agent 在已批准的远程会话中向设备用户提一个问题，给出几个选项。客户端弹出与现有窗口一致的询问框，用户可以单选，也可以通过始终可见的输入框回答选项之外的内容；回复以结构化结果返回 Agent。

首版只做：

- 单个问题、单选、自由输入、提交、暂不回答。
- 每台设备同时最多一个待回复问题，超出返回 `QUESTION_BUSY`，不排队、不叠弹窗。
- 默认等待 120 秒，可指定 15–300 秒；不能超过会话剩余有效期。
- 复用现有 MCP → Go platformclient → platform core → Qt 客户端链路。
- 纯内存状态，随会话清理；不新增数据库、服务、消息队列、Web 页面或长连接。

暂不做：多选、多题表单、聊天记录、附件、Markdown/HTML、可配置窗口样式、跨会话恢复、未授权时弹窗。

## 2. Agent 工具接口

### `ask_user`

```json
{
  "session_id": "已批准的会话",
  "question": "你希望把软件安装在哪里？",
  "options": ["默认位置", "D 盘", "只下载，暂不安装"],
  "timeout_seconds": 120
}
```

- 必填 `session_id`、`question`。
- `question`：去除首尾空白后 1–1000 个 Unicode 字符。
- `options`：可省略，0–6 个字符串；每项去除首尾空白后 1–100 个 Unicode 字符，不允许空项、重复项。
- 不提供选项时为纯输入询问，仍使用同一个弹窗。
- `timeout_seconds`：可选，默认 120，范围 15–300。
- 成功表示平台接收并转发，不表示用户已看到或已回答。

```json
{
  "ok": true,
  "code": "OK",
  "data": {
    "session_id": "…",
    "request_id": "…",
    "status": "pending",
    "expires_at": 1770000000
  }
}
```

### `get_user_reply`

参数只有 `session_id`、`request_id`，立即读取当前状态，不长时间阻塞。

用户选择已有选项：

```json
{
  "status": "answered",
  "answer_source": "option",
  "selected_index": 1,
  "answer": "D 盘"
}
```

用户自由输入：

```json
{
  "status": "answered",
  "answer_source": "text",
  "answer": "请安装到 E:\\Apps"
}
```

以上内容放在现有统一响应的 `data` 中，并包含 `session_id`、`request_id`。下标从 0 开始，自由输入时不返回 `selected_index`，不使用含糊的 -1。

工具说明要求 Agent：等待期间不要执行依赖这个回答的操作，不要连续重复发问；查询仍为 `pending` 时稍后再查，不忙轮询；取消、超时和结果未知都不代表同意。

### 为什么拆成两个工具

当前 `internal/platformclient/client.go` 在请求交互期间持有 `requestMu`。不把等待用户的几分钟放进 `sendRequest`，避免阻塞同连接上的其他调用，尤其是 `close_session`。沿用已有“提交命令 + 查询结果”的模式，不为此重构整个工具并发模型。

## 3. 客户端交互与样式

```text
┌ 远程协助询问                         × ┐
│ 当前远程协助的 Agent 需要你回答         │
│                                       │
│ 你希望把软件安装在哪里？                │
│                                       │
│ ○ 默认位置                             │
│ ○ D 盘                                 │
│ ○ 只下载，暂不安装                      │
│ ○ 其他回答                             │
│ [ 输入其他选择或说明……               ] │
│                                       │
│ 剩余 1:59           [暂不回答] [提交回复]│
└───────────────────────────────────────┘
```

行为：

1. 所有选项初始不选；无有效内容时“提交回复”禁用，不能 Enter 误提交默认选择。
2. 输入框始终显示。输入非空文字自动选中“其他回答”；选择已有选项则提交该选项，不把残留文字混入回复。
3. 自由输入最多 1000 个 Unicode 字符；空白不能提交。用 `QLineEdit`，首版不新增多行编辑器样式。
4. 关闭按钮、Esc、“暂不回答”统一返回 `cancelled`，绝不自动选择第一项。
5. 一次提交后立即禁用控件，避免双击重复回包；结果上报后关闭窗口。
6. 使用异步 `open()` + 信号处理，不在网络回调中嵌套 `exec()`；WebSocket、心跳、超时与会话终止仍正常工作。
7. 主窗口隐藏到托盘时，询问框仍可独立显示；不先恢复整个主窗口，不设为永久置顶。调用标准激活请求；Windows 不允许抢焦点时使用任务栏提醒/托盘通知作为补充。
8. 父窗口隐藏或在屏幕外时，弹窗定位到当前可用屏幕区域；多显示器、缩放后不越界。
9. 等待期间会话结束、平台断开或超时，立即关闭并清理弹窗，不能提交旧回复。

样式硬约束：

- 严格遵循 `qt-client/UI_STYLE.md`。
- 复用 `YiukDialog`、现有 `TitleBar`、`makeLabel`、`addButton`，固定本地标题“远程协助询问”。不允许 Agent 伪装系统窗口标题。
- 沿用白底、冷灰边框、浅投影、蓝色主按钮、自绘标题栏和现有字号间距；宽度约 520–560px，按屏幕限制高度，长问题/选项换行，必要时只让正文滚动。
- 输入框使用现有 `settingsField`；选项使用现有 `QRadioButton` 风格，文字较长时配换行标签，不裁切。
- 所有 Agent 提供的文字按纯文本显示，不解释链接、HTML 或 Markdown。
- 不使用 `QMessageBox`、`QInputDialog`、原生 Windows 弹窗或新的一套 QSS。
- 增加独立的 `userquestion.cpp/.h` 管理组装与生命周期，组合现有 final 的 `YiukDialog`，不为单一功能改成通用表单框架。

## 4. 平台与协议：只增加必要能力

复用协议版本和现有 `session_id`、`request_id`、`status`、`expires_at`、`correlation_id` 等字段，增加问题、选项及回复字段。新增消息：

| 消息 | 方向 / 用途 |
| --- | --- |
| `ask_user` | 操作端 → 平台 → 目标设备，发起询问 |
| `user_question_accepted` | 平台 → 操作端，快速确认接收并返回到期时间 |
| `user_reply` | 设备 → 平台，上报用户回复或取消；也用于平台返回查询结果 |
| `get_user_reply` | 操作端 → 平台，查询结果 |
| `cancel_user_question` | 平台 → 设备，通知问题到期或随会话终止；不额外暴露 MCP 工具 |

平台新增一个小型问题状态管理器，独立于 PowerShell task，不把用户选择塞进 stdout/exit_code。记录原问题、选项、会话绑定、到期时间和单次终态结果；复用现有 janitor 定时清理与会话生命周期钩子。

安全与正确性：

- 发问、查询都校验操作者连接归属及有效会话；首版复用 `execute_command` 会话授权，不新增权限申请页面或权限体系。仅查询结果也不能跨会话读取。
- 设备回包必须来自会话绑定的原设备连接，不只检查 `device_id`。
- 参数在工具层、平台层校验，Qt 对收到的长度、状态、结构再做防御性校验。
- 选项回复必须有合法下标，由平台根据原选项生成 `answer`；不信任设备随意填写的选项文本。
- 请求 ID 按现有规则生成；同一会话下相同请求 ID 不重复弹窗，payload 不一致则拒绝。重复终态回包不覆盖原结果。
- 每会话累计提问数量沿用任务数量上限，防止无限弹窗/结果缓存增长。
- 问题及用户原文不进入平台日志、支持报告或客户端持久化文件；活动面板只记录“Agent 发起询问 / 用户已回答 / 用户取消 / 超时”等摘要。
- 回复仅表达意愿，不授予额外权限，不等于执行授权，不自动执行选项文字。工具说明禁止通过此窗口索取密码、验证码、私钥等敏感凭据。

状态约定：

| 状态 | 含义 |
| --- | --- |
| `pending` | 正在等待用户 |
| `answered` | 用户明确提交了回复 |
| `cancelled` | 用户选择暂不回答，或会话正常结束 |
| `timed_out` | 问题到期仍未回复 |
| `result_unknown` | 连接中断，平台无法确认最终回复 |

终态只写入一次，迟到回复不能复活。到期/关闭与回复并发时以平台状态原子收敛的结果为准。平台重启不恢复问题；记录不存在应明确返回错误，Agent 不得自动重新弹窗。

兼容旧客户端：旧版可能忽略未知消息。首版不加复杂能力协商；超时提示明确写“未收到回复，可能用户未回答或客户端不支持此功能”，不伪造“用户拒绝”。平台/客户端共同升级后启用。

## 5. 分步实施及修改位置

### 第一步：协议、状态与平台

- `internal/platform/protocol/protocol.go`：新增消息及字段。
- 新增问题管理器及单元测试；在 core `service.go` 接入。
- 新增 `internal/platform/core/handler_question.go`；在 `handler.go` 分发。
- `janitor.go`、会话关闭/断线分支：收敛问题并通知设备关闭弹窗。
- 网关/edge 先核查是否透明转发消息，只在确有白名单处补充，不增加专用 RPC 或服务。

### 第二步：Agent 工具

- `internal/agenttools/tools.go`：注册两个工具、schema、严格参数校验和描述。
- 新增 `internal/platformclient/tools_question.go`，在 `client.go` 接入分发；提交与查询均为短请求。
- `mcpadapter` 沿用已有工具目录生成机制，不加专门适配层。
- 本地桥接路径在 `qt-client/src/localtools.cpp` 接入同一询问控制器，避免工具目录已公开却只在远程后端可用；不复制弹窗代码。

### 第三步：Qt 客户端

- `platformclient.h/.cpp`：接收提问/取消，发送回复。
- `platformlink.cpp`：连接相应信号。
- `userquestion.cpp/.h`、`mainwindow.h`：管理唯一待回复窗口、计时、提交与清理；CMake 注册源文件。
- 会话结束、过期、平台断开、本地关闭统一进入问题清理函数。
- 弹窗不依赖主窗口当前页面，不改动已有授权流程。

### 第四步：测试与说明

- 参数测试：中文/emoji、空白、重复选项、长度边界、未知字段、非法下标。
- 平台测试：无授权/错误连接拒绝、跨会话拒绝、重复请求不重弹、同设备并发 busy、超时、断线、会话关闭、迟到/重复回包、终态竞态。
- 联调：选择选项、自定义回复、纯输入问题、取消均能从 MCP 取回正确结构。
- UI 验收：主窗口显示/隐藏、浅深任务栏、多屏、100%/125%/150% DPI、长问题和长选项；外观与现有授权/输入弹窗一致。
- 等待回复期间验证心跳不中断、查询状态和结束会话可用，正常结束会话后窗口立即消失。
- 更新工具列表/使用说明，补 Qt↔Go 互操作测试；旧客户端超时不误报拒绝。

## 6. 完成标准

Agent 用一次 `ask_user` 在目标客户端发起询问；用户可选择任意选项或输入自己的答案；Agent 用 `get_user_reply` 取得明确结果。取消、超时和断线不冒充回答。客户端复用现有窗口风格，无弹窗堆叠、无阻塞等待、无额外基础设施。

## 7. 实施中的小调整

- 当前 `MaxTasksPerSession` 实际限制同时运行的命令数，默认仅 2，不适合作累计提问次数。因此询问记录使用独立的固定上限 32 条/会话，不新增配置项。
- `YiukDialog` 用异步 `show()`，并将此询问窗口设为非模态，保证主窗口的停止会话入口始终可用；不使用嵌套事件循环。
- 增加设备上报 `user_question_failed` 消息表示无法显示/接受窗口，平台收敛为 `result_unknown`，不伪造用户取消。
- 平台/客户端统一使用整秒截止时间；客户端计时到期只关闭 UI，由平台权威收敛超时结果。
- 新增可选真实 Qt + MCP stdio 端到端测试目标 `yiuk-question-interop`，仅在启用测试构建时生成。
- 界面在第二轮自查后重做：取消单选框与隐藏联动规则，改为“点选项即回答 + 直接输入/Enter 发送”；删除倒计时与说教文字；长内容才滚动；询问窗口置顶并在托盘隐藏时提醒；修正空输入按 Enter 会误选第一项、以及无边框窗口被遮住看不到的问题。详见 [user-questions-test-report.md](user-questions-test-report.md)。
