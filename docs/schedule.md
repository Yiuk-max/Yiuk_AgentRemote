# Yiuk Switchboard 工期与推进计划

版本：1.1  
状态：单人 + AI Agent 粗估，按阶段验收，不是日期承诺  
人员假设：没有工程师团队；项目所有者负责决策、提供环境和少量真实验收，AI coding agent 承担主要代码修改、测试编写和文档维护。  
关联文档：[产品需求](product-requirements.md)、[技术选型](technical-selection.md)、[实现方案](implementation.md)

## 1. 当前 P0 与估算结论

当前 P0 已收敛为“Agent 适配 + 统一工具”：先完成稳定的 Agent 无关工具契约和 MCP stdio adapter，用 fake backend 验证发现、调用、结构化响应和错误映射。P0 不包含 Qt UI、设备在线连接、账户/设备注册和 PowerShell 远程执行。

按 AI Agent 协助实现、项目所有者可用 MCP Host 实际配置验证的假设，P0 预计 2-5 个有效工作日。当前代码已完成工具核心、8 个 MCP 工具注册、参数校验和 SDK 内存传输集成测试；剩余的关键验收是接入一个真实 Agent/MCP Host 做启动和工具发现验证，以及稳定契约审查。

不按传统“几名工程师”计算。AI Agent 可以快速生成和修改代码，但不能替代真实 Windows、两台跨网络设备、目标 Agent 和 Minecraft 客户端上的验收；仓库改动也需要逐步验证，不能把代码生成速度当作项目交付速度。

在项目所有者每周能投入约 3-6 小时做需求确认、构建/运行、跨设备测试和反馈的假设下：

- **后续本机技术验证：约 1-3 周**。完成当前 P0 后，再确认 Qt Windows 构建、PowerShell 执行和 TLS TCP 原型的关键风险。
- **两台 Windows 设备的最小远程闭环：约 4-8 周**。手动配置设备、一次明确批准、执行命令、返回输出和退出码；先不追求完整账户、安装升级体验。
- **可邀请少量用户试用的 MVP：约 10-20 周或更长**。补足设备注册、凭证撤销、安装包、异常处理、安全测试、真实 Agent E2E 和 Minecraft 回归。
- **Minecraft 适配/回归**：可能与主线交错，也可能成为发布阻塞项；估算约 2-8 周，若旧客户端/测试环境不可用或协议耦合复杂则无法可靠预估。

若项目所有者每周只能投入 1-2 小时，日历时间可能达到上述估算的 2-3 倍；若不能持续提供双机和 Minecraft 验收环境，相关里程碑会停在“代码已实现、未验证”，不能称为完成。

## 2. 估算口径与假设

- 一名项目所有者，不招聘、不假设有专职工程师或独立 QA。
- AI Agent 逐任务实现、运行可用的自动化测试、检查 diff 和维护文档；每次改动范围需可审查、可回退。
- 项目所有者每周可投入约 3-6 小时，负责确认交互、安全决策、提供 Windows/Minecraft 环境并实际运行验收步骤。
- 目标 Windows 10/11 x64；本机可安装 Qt 6/C++/CMake/Go 工具链并构建桌面程序。
- 项目所有者能使用两台 Windows 设备或一台 Windows VM 加另一台物理设备，并可测试不同网络/NAT。
- 首发一个 MCP adapter 和一个真实 Agent；先做最小可用的用户/设备配对方式，不做企业账户体系。
- 不做图形远控、管理员默认提权、计费、云端高可用或多区域部署。
- Minecraft 有当前版本的客户端、MOD 和可运行测试环境；若没有，先找回/构建基线会增加未知工期。

## 3. 由项目所有者提供的不可替代输入

AI Agent 可以生成测试和步骤，但不能在未连接的真实设备上替你验证，也不能替你同意产品安全边界。每阶段需要的用户投入应尽量集中成一次验收包：

- **决策**：确定设备配对/登录方式、退出 UI 后是否在线、是否接受 relay 能读取经过 TLS 解密后的命令数据、Minecraft 必须保留哪些操作。
- **环境**：提供 Windows 构建机、第二台 Windows 测试设备、目标 Agent 的本地配置权限、Minecraft/loader 客户端与测试账号。
- **验收**：实际安装/运行程序、批准/拒绝一次请求、验证命令结果/中断行为、完成 Minecraft 开房和加入测试。
- **发布**：确认应用名称/图标、签名证书或接受未签名测试包、选择分发方式。

为降低时间成本，优先让 Agent 提供一页式验收清单、自动化脚本、日志采集方式和明确通过/失败判据。未经项目所有者真实验收的网络授权、安全和 Minecraft 项目必须标注“未验证”。

## 4. Agent 驱动的阶段计划

| 阶段 | 预计日历时间* | Agent 主要工作 | 项目所有者需要做什么 | 退出条件 |
| --- | --- | --- | --- | --- |
| P0. 统一工具与 MCP | 2-5 个有效工作日 | 固定 8 个工具契约、MCP stdio adapter、fake backend 和自动化测试 | 在目标 Agent/MCP Host 配置本地进程并确认工具可见、调用成功 | 一个真实 Host 能发现工具并获得稳定结构化结果；无 backend 时正确报错 |
| 0. 范围与决策冻结 | 2-5 天 | 整理流程、威胁模型、Minecraft 兼容清单、最小账户方案 | 回答文档待决项；确认不可妥协安全规则 | 无关键冲突；有可执行验收清单 |
| 1. 本机 spike | 1-2 周 | Qt/CMake 空壳、QProcess 输出/编码/超时实验、MCP stdio demo、TCP/TLS 连接 demo | 在本机安装依赖并运行；选择首个 Agent | PowerShell 与 MCP 的实际接口已跑通；风险有结论 |
| 2. 远程最小闭环 | 2-4 周 | Go TLS TCP relay、临时设备身份、请求/批准状态、单命令与结果回传、mock 测试 | 准备第二台 Windows 设备；跨网络运行一次完整流程 | 未批准无法执行；批准后命令成功返回；停止可中断 |
| 3. 基础产品化 | 2-4 周 | Qt 所有者/协助者界面、设备注册、会话显示、撤销、限额、错误处理、MCP 工具 | 验收拒绝/过期/断网/重复请求；配置真实 Agent | 两台设备经 MCP 完成多轮任务，状态准确 |
| 4. 安全与安装 | 2-4 周 | 凭证保护、审计脱敏、进程树清理、安装包、干净环境测试、安全用例 | 安装/卸载测试；审查授权文案；验证取消和日志 | MVP 安全与安装清单通过 |
| 5. Minecraft 兼容 | 2-8 周（高不确定性） | 依冻结清单选择旧协议适配、新旧服务并行或 MOD 迁移 | 启动目标游戏版本、两名玩家实测开房/加入/双向数据 | 目标 Minecraft 用例真实通过；否则不宣称保留验收完成 |

*日历时间以每周项目所有者投入 3-6 小时、AI Agent 可持续执行代码任务为假设。阶段可能反复；总时间不能简单相加。Minecraft 可以提前并行摸底，但在没有实际客户端环境时只能完成代码分析。

## 5. 建议的最小切片

不要一开始同时做完善 GUI、账号系统、安装升级和全部 MCP 工具。优先让一个可控闭环尽早运行：

1. 本机 Qt 小程序通过 `QProcess` 启动 PowerShell，返回 stdout、stderr、退出码；测试超时、非 ASCII 和取消。
2. 同一个 Qt 可执行文件提供 MCP stdio 模式；先由一个目标 Agent 调用本地测试工具。
3. Go 服务接受两条 TLS TCP 客户端连接，路由带请求 ID 的消息；先用 mock device/operator 验证授权门禁。
4. 两台 Windows 设备接入；设备 UI 收到请求后人工批准，只允许该会话执行一条命令。
5. 补齐设备凭证、会话撤销、任务限额、安装包与 Minecraft 回归。

这个顺序先暴露技术风险，避免把大量时间投入一个尚未打通真实网络/Agent 的完整 UI。

## 6. 风险与工期影响

| 风险 | 对工期的影响 | 应对 |
| --- | --- | --- |
| 项目所有者可投入时间不足 | 日历时间按比例延长；反馈等待会成为主瓶颈 | 每次会话集中处理一批明确问题；优先交付可直接运行的验收包 |
| Qt/Windows 工具链首次配置 | 可能增加数天至数周 | 阶段 1 先完成空项目构建和依赖记录 |
| 目标 Agent 的 MCP stdio 生命周期不兼容 | 约增加 1-3 周或需调整 adapter 形式 | 先选定一个 Agent 做 spike，不先承诺多 Agent |
| NAT/防火墙环境阻断 TCP 端口 | 约增加 1-4 周，可能需要 WSS fallback | 早期用真实网络验证；不要只在 localhost 测试 |
| PowerShell 进程树取消/输出编码问题 | 约增加 1-3 周 | 先做 Job Object、持续输出、非 ASCII 和断线实验 |
| 账户配对/凭证恢复未定义 | 约增加 1-4 周 | MVP 先选单一简化流程，设备码不作秘密 |
| relay TLS 终止后的隐私接受度 | 若要求端到端加密，可能增加 2-6 周 | 先明确中转威胁模型；不把 TLS 说成端到端加密 |
| Minecraft 环境或旧版本素材不可用 | 无法估准，可能阻止发布 | 尽早确认客户端、loader、MOD 和可复现步骤 |
| AI Agent 生成错误或过度改动 | 返工时间不定 | 小步修改、自动测试、代码 diff 审查，不让一次任务跨全部模块 |

## 7. 里程碑与停止条件

- **M1：本机风险清楚**。Qt 可构建，PowerShell 和 MCP spike 能运行，TCP/TLS 方案有真实网络测试计划。
- **M2：双机闭环**。未批准不能执行；批准后命令可返回；设备所有者可停止。此时才值得扩展产品功能。
- **M3：Agent 闭环**。一个真实 Agent 能申请连接、等待批准、连续执行两条命令并关闭会话。
- **M4：可试用候选版**。安装、凭证撤销、取消/断线、安全检查通过；Minecraft 兼容用例通过或明确作为发布阻塞项。

若项目所有者暂时无法提供第二台设备、目标 Agent 或 Minecraft 环境，应停止在对应阶段并记录未验证项；不要用 mock 测试结果替代端到端验收。

## 8. 工期更新规则

完成阶段 1 后，基于实际工具链安装耗时、MCP spike、QProcess 测试和网络条件重新估算。每完成一个里程碑，用实际投入时间修正后续范围。优先缩减非核心 UI/自动升级/账户体验，不缩减用户授权、可立即停止、凭证保护、任务限额或 Minecraft 兼容验收。
