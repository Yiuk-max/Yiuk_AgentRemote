# Yiuk Switchboard 技术选型

版本：1.0  
状态：建议基线，阶段一原型验证后冻结  
关联文档：[产品需求](product-requirements.md)、[实现方案](implementation.md)、[工期估算](schedule.md)、[后端实施状态](backend-status.md)

## 1. 选型目标

构建面向 AI Agent 的远程 Windows 协助平台。协助者和被协助者使用同一款 Windows Qt 软件；操作者电脑上的 Agent 通过统一工具能力访问设备；被协助者必须明确授权。既有 Minecraft 联机能力是兼容要求，不是新平台的架构约束。允许重构或替换 Go 后端和协议，必要时适配 Minecraft MOD。

## 2. 决策摘要

| 领域 | 选型 | 说明 |
| --- | --- | --- |
| 桌面应用 | Qt 6 Widgets，C++，CMake | 一个 Windows 安装产品，提供协助者、设备所有者和后台模式；UI 与网络/执行逻辑分层 |
| 中转服务 | Go | 复用语言和部分网络经验；现有 relay 可重构或替换，不承诺兼容旧协议 |
| Agent 集成 | 独立的 MCP stdio adapter，首发 | Agent 通过本机子进程标准输入输出调用工具；共享稳定的内部能力接口，后续可加 adapter |
| 客户端到服务端传输 | 长连接 TCP + TLS 1.3，应用层长度前缀帧 | 主动出站连接适配 NAT；协议控制消息和数据消息均有大小限制、版本、请求 ID |
| 设备执行 | Windows 端任务执行模块 + PowerShell 7 优先、Windows PowerShell 5.1 fallback | 使用 `QProcess` 或同一执行模块封装系统进程；明确超时、取消、编码和输出上限 |
| 身份和授权 | 设备独立凭证、操作者账户/凭证、一次性会话授权 | 设备码仅作查找标识；连接须由设备所有者逐次批准，撤销即时生效 |
| Minecraft | 独立业务类型/会话域，按兼容测试保留行为 | 可调整 relay/MOD；不与 Agent 设备会话共享授权或状态机 |
| 部署 | 早期单一 Go 服务进程，逻辑模块分层 | MVP 避免过早拆微服务；TLS 可在 Go 服务终止，但安全设计需明确中转可见性 |

## 3. 客户端形态

采用同一个安装包、同一套 Qt 客户端代码，不要求两端具有相同运行角色：

- **设备所有者模式**：设备注册、在线状态、连接申请、批准/拒绝、活动会话和立即停止。
- **协助者模式**：账户/设备访问、连接申请、会话和任务状态；本机 Agent 通过 MCP adapter 调用。
- **MCP 模式**：同一产品附带的命令行子模式，由 Agent 按 MCP 配置启动，通过 stdio 服务工具；不要求 GUI 常驻在协助者侧。

设备常驻连接可由 Qt 程序自身承载。MVP 是否需要 Windows 服务取决于“退出 UI 后是否仍需在线”这一产品决定；默认 MVP 不做隐蔽常驻，用户退出即离线。若后续安装 Windows Service，必须在系统托盘/UI 明确显示并提供停止入口。

## 4. 通信和中转

使用 TLS 保护客户端至 Go 服务的 TCP 长连接。应用层采用带长度前缀的版本化消息帧。消息类型区分认证、设备注册/心跳、连接申请/决定、会话控制、命令任务、命令输出块和完成状态。服务端仅向已授权且绑定到具体会话的两端路由消息。

TCP 可用于控制和任务流，不要求另建 UDP。所有连接均由客户端主动连出，适用于常见 NAT。必须实现心跳、超时、背压、最大帧长、速率/并发限制、断线清理及协议版本协商。

MVP 采用 TLS 传输加密；TLS 在中转终止意味着服务端在路由层可能接触明文应用帧。服务端不得持久记录命令正文或输出。若产品要求中转服务运营者也无法读取会话内容，应在发布前增加端到端加密设计，不能把 TLS 等同于端到端加密。

Minecraft 游戏字节流可继续由 TCP 中转。Minecraft 控制协议和远程协助协议须以业务类型隔离，使用独立会话标识、认证授权和资源限制；不允许 Agent 会话凭证获得 Minecraft 房间权限，反之亦然。

## 5. Agent 工具接口（当前 P0）

统一工具核心和 MCP stdio adapter 已完成；Qt 客户端已提供本机 loopback bridge，可由本地 `yiuk-mcp` 访问本机设备和会话能力。当前 bridge 只支持本机设备，远程平台 backend 尚未接入；未配置远端 backend 时仍返回明确错误，不伪造设备在线或远程执行结果。

先定义语言/进程边界无关的工具契约：工具名、输入 schema、结构化输出、错误码、超时与取消语义。MCP adapter 只做协议映射，不承担设备授权、命令执行或业务状态管理。

首发建议工具：`list_devices`、`get_device_status`、`request_connection`、`run_command`、`get_session_status`、`execute_command`、`get_command_result`、`download_file`、`cancel_command`、`close_session`。文件下载需要独立的 `read_file` 会话权限和字节上限，不能复用命令输出通道。长任务使用任务 ID 和结果读取/事件通知，不能让单个 MCP 调用无限挂起。

MCP 传输选 stdio，便于各 Agent 用本机进程配置启动。adapter 通过本机 IPC/受限 loopback API 调用桌面应用核心，或者独立实现连接客户端。阶段一原型需验证目标 Agent 的 MCP 配置、进程生命周期、错误展示和多 Agent 并存行为后，冻结进程边界。

## 6. Windows 命令执行

Qt 可用 `QProcess` 启动 PowerShell 并异步读取 stdout/stderr。执行模块必须提供：任务 ID、工作目录、超时、输出上限、取消、退出码、编码策略和状态转换。启动参数应按独立参数传递，不经 `cmd.exe` 二次解析；脚本文本通过临时受限文件或 UTF-16LE Base64 参数传递，并验证清理行为。

PowerShell 命令执行本质上允许该 Windows 用户权限范围内的任意操作，普通用户权限不等于沙箱。MVP 以每会话所有者批准、默认不提权、可见活动状态、执行时限/输出限制、会话立即撤销作为基线。不得宣称命令白名单能构成可靠安全边界。

取消必须处理子进程树。Windows 可使用 Job Object 管理进程树；结束任务时先请求正常终止，超时后强制结束 Job。断线策略 MVP 选“会话失效即取消未完成任务”，并将无法确认的终态报告为 `result_unknown`。

## 7. 备选与取舍

- **Qt/C++ 与 Go 执行 Agent 分进程**：隔离性较好，但增加安装、IPC、升级和故障诊断复杂度。仅在原型证明 QProcess/Qt 线程模型无法满足时拆分。
- **HTTP/WebSocket**：便于调试和代理穿透，但需另行处理长会话与二进制/分块流。MVP TCP TLS 更贴近现有 relay；若部署网络封锁非标准端口，再考虑 HTTPS/WSS fallback。
- **复用旧 Protobuf**：可节省协议工作，但字段语义绑定 Minecraft。除非评估证明协议边界干净，否则新产品定义独立 schema；Minecraft 旧协议通过适配层或版本化兼容实现保留。
- **Web UI**：当前用户明确偏好 Qt，故不作为首版方案。
- **MCP 直接写入 Qt 主程序**：部署简单但 GUI 生命周期不适合 stdio 子进程。应保持 MCP adapter 为同产品中的单独运行模式或轻量进程。

## 8. 技术栈版本基线

- Qt 6.8 LTS 或项目可获得的受支持 Qt 6 LTS；Windows x64。
- C++17，CMake；Qt Core、Widgets、Network、Test。
- Go 当前稳定版本；模块版本与 CI 镜像固定，升级单独评审。
- MCP SDK/实现按目标 Agent 兼容性评估后固定具体版本；MCP 协议版本纳入兼容测试。
- TLS 1.3 优先，必要时 TLS 1.2；证书校验不可关闭。

版本应在阶段一根据 Windows 支持周期、Qt 授权/分发方式、MCP SDK 状况和 CI 可用性确认。

## 9. 决策门槛

正式远程实现仍须验证：同一 Qt 程序能运行设备所有者模式和协助者模式；设备注册和凭证撤销可用；至少一个目标 Agent 能通过 MCP stdio 调用本机和远程工具；NAT 两侧均只主动出站仍可建立授权会话；PowerShell 输出/超时/取消可正确回传；Minecraft 兼容行为清单已冻结。任何一项失败都应更新技术选型和工期估算。

当前 Qt UI 已完成的界面基线：主页、设备码输入、添加设备、设备列表、复制本机设备码、会话记录和本机协助设置。设备列表中的本机设备与本地保存的远程设备码必须与平台在线状态区分显示。
